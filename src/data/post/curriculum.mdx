# Coding Club Curriculum (Updated Nov 17, 2026)
## Friday After-School Meetings | 3:15-4:00 PM

**Goal:** Get everyone to the same level (JS/TS fundamentals + basic web skills + SvelteKit basics) so the club can build a project together.

**Final deliverable:** Team-built web app solving a real problem, shown at the last meeting.

**Why this was rebuilt:** The club fell behind because of Parent-Teacher Conferences (Oct 8-9) and Día del Profesor. Dates below are real Fridays checked against the school calendar. Summer vacation (Dec 21 - Feb 14) splits the year into two halves.

## KNOWN TIGHT SPOTS

1. **The final project only gets about 2.5 build meetings** (May 28, Jun 4, plus planning on May 14). Scope it small. If you want more, the easiest trades are:
   - Drop Capstone 1 (the weather app already works as a practice project), which frees Feb 26 and Mar 5-ish for a build week
   - Merge weather app parts 1 and 2 into one meeting
2. **Two-week gaps** happen at Mar 19 → Apr 2, Apr 9 → Apr 23, and May 14 → May 28. Start those meetings with a 5-minute "where were we" recap.
3. **Two-month summer gap** (Dec 11 → Feb 19) will cost some retention. The Capstone 1 kickoff is designed to double as the refresher.
4. **Unlisted events** (exams, field trips, school events) aren't on the calendar. Watch for them in March-May.
5. **If you slip again:** cut from spring first (Svelte routing, then weather app part 2). Do not cut fall fundamentals, since leveling everyone up is the point.

## MEETING FORMAT (45 minutes, ~35-40 of real teaching)

- **3-5 min:** Recap with a recall opener (2-3 predict-the-output questions on last week)
- **25-30 min:** Live coding + short activities (everyone codes along, predict-then-run)
- **3-5 min:** Wrap-up, homework
- **Pause points:** finger check (1 = lost, 2 = mostly, 3 = got it) after each step. If two or more students show 1, redo the step with a different example
- **Mixed levels:** pair a comfortable student with a newcomer. Keep 2-3 fast-finisher challenges ready every week
- **Catch-up code:** push each meeting's finished code to the GitHub org so anyone who missed or fell behind can copy it
- **Say "when to use it":** attach a one-line "use this when..." to every new concept, and share a short cheat sheet in the group chat
- Don't put critical content in the last 5 minutes (people leave for sports)
