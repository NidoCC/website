# Coding Club Curriculum: Week-by-Week (Revised)
## 2026-2027 School Year | Start Date: August 24, 2026
### 24-26 Active Teaching Weeks | Focus: Level-Setting for Collaborative Projects

**Overall Goal:** Get everyone to the same level (JavaScript fundamentals + basic web skills) so the club can work on real projects together.

**End-of-Year Deliverable:** Team-built web app/website solving a real problem.

---

## PHASE 1: FOUNDATIONS (8 Weeks)
### August 24 - October 16, 2026
**Goal:** Solid JavaScript/TypeScript fundamentals—everyone at the same level

---

## **Week 1: August 24-30, 2026**
### Welcome & Setup + First Variables

**Topics:**
- Club overview and expectations
- Environment setup (Node.js, VS Code, Git/GitHub)
- Variables (`let`, `const`)
- Simple assignments

**Activities:**
- Icebreaker (5 min): Names, grade, previous coding experience, what they want to build
- Club expectations (3 min): Show up, good attitude, no phones
- Install Node.js and VS Code (15 min): Help troubleshoot
- GitHub setup (3 min): Collect emails, invite to org after
- Hello World in TypeScript (15 min): Follow your existing process
- One simple variable (4 min): `let name = "YOUR_NAME"` and `console.log(name)`

**Homework:**
- Make sure everything installs
- Create 3 variables with meaningful names

**Teaching Notes:**
- Don't try to cover too much—setup is the main goal
- They'll feel accomplished just running code
- One variable is enough for Week 1

---

## **Week 2: August 31 - September 6, 2026**
### Data Types & Operators (Part 1)

**Topics:**
- Data types (string, number, boolean) — formalize it
- Arithmetic operators (`+`, `-`, `*`, `/`, `%`)
- Comparison operators (`===`, `!==`, `>`, `<`, `>=`, `<=`)

**Activities:**
- Live code: Create variables of each type, show what they look like
- Explain: "TypeScript cares about what type things are"
- Live code: Arithmetic on numbers
- Group exercise: Do some calculations together
- Live code: Comparison operators make booleans
- Challenge: Predict what `5 > 3` returns

**Homework:**
- Create variables of each type
- Do some arithmetic and comparisons
- Write comments explaining what each line does

**Teaching Notes:**
- Data types are fundamental
- Comparisons create booleans—show this explicitly
- Modulus is confusing; use the pizza/clock analogy
- Don't go deep on TypeScript yet; just show it catches mistakes

---

## **Week 3: September 7-13, 2026**
### Strings, Template Literals & Logical Operators

**Topics:**
- String methods (`.length`, `.toUpperCase()`, `.toLowerCase()`, `.slice()`)
- Template literals (`` `Hello ${name}` ``)
- Logical operators (`&&`, `||`, `!`)

**Activities:**
- Live code: Use string methods on variables
- Show: Template literals vs. concatenation (side-by-side)
- Group exercise: Create a greeting using template literals
- Explain: Logical operators combine booleans
- Live code: `true && false`, `true || false`, `!true`
- Challenge: Combine comparison operators with logical operators

**Homework:**
- Use string methods on different strings
- Create a formatted message using template literals
- Predict the output of logical operator combinations

**Teaching Notes:**
- Template literals are powerful—show why they're better than `+`
- Logical operators take practice; do several live examples
- String methods are just function calls on data
- Don't worry about all string methods; show the most common ones

---

## **Week 4: September 14-20, 2026**
### Control Flow: If/Else & Ternary

**Topics:**
- `if`, `else if`, `else` statements
- Ternary operator (`condition ? trueValue : falseValue`)
- Nested conditionals (brief)

**Activities:**
- Live code: Grade checker (score → A/B/C/D/F)
- Live code: Age-based messaging
- Group exercise: Write if/else for a simple problem
- Introduce ternary as shorthand
- Live code: Rewrite an if/else as ternary
- Challenge: Nested conditions (age AND grade level)

**Homework:**
- Write an if/else program for something meaningful
- Rewrite part of it using ternary operators

**Teaching Notes:**
- If/else is fundamental—take time here
- Ternary is syntax sugar; if is clearer for complex logic
- Nesting is okay but readability matters
- Show how indentation makes code readable

---

## **Week 5: September 21-27, 2026**
### Loops: For & While

**Topics:**
- `for` loops (syntax and patterns)
- `while` loops
- `break` and `continue`
- Common loop patterns (counting, summing, finding)

**Activities:**
- Live code: Print numbers 1-10 with a for loop
- Live code: Sum all numbers 1-100
- Live code: Find first number divisible by 3 and 5
- Group exercise: Write a loop to do something simple
- Live code: When to use while vs. for
- Challenge: Nested loops or break/continue

**Homework:**
- Write a for loop that does something meaningful
- Write a while loop for something else
- Experiment with break and continue

**Teaching Notes:**
- Loops are a pattern—help them recognize when they need them
- Infinite loops are dangerous but instructive; let them experience one briefly
- Off-by-one errors are common; help them debug
- Nested loops are confusing; don't overuse

---

## **Week 6: October 5-11, 2026**
### Functions (Part 1): Declarations & Scope

**Topics:**
- Function declarations (`function greet(name) { }`)
- Parameters and return values
- Scope (local vs. global)
- Why functions matter (reusability, organization)

**Activities:**
- Live code: Write simple functions (`add`, `greet`, `isEven`)
- Explain: Functions are reusable chunks of code
- Group exercise: Write a function with multiple parameters
- Live code: Show what happens without a return
- Explain scope: Which variables can be accessed where?
- Challenge: Function that calls another function

**Homework:**
- Write 3-4 functions of your choice
- Comment what each function does

**Teaching Notes:**
- Functions are fundamental to programming
- Parameters are inputs, return is output—use this language
- Scope is confusing; use visual examples or diagrams
- They don't need to master functions yet; they'll use them constantly

---

## **Week 7: October 12-18, 2026**
### Functions (Part 2): Arrow Functions & Array Methods

**Topics:**
- Arrow functions (`const add = (a, b) => a + b`)
- Anonymous functions
- Callbacks (introduction)
- Array methods (`.map()`, `.filter()`, `.forEach()`)

**Activities:**
- Live code: Rewrite Week 6 functions as arrow functions
- Show: Both syntaxes side-by-side
- Introduce callbacks: "A function as an argument"
- Live code: `.forEach()` to loop through array
- Live code: `.map()` to transform array
- Live code: `.filter()` to get subset of array
- Challenge: Chain methods together

**Homework:**
- Rewrite functions as arrow functions
- Use array methods on a list

**Teaching Notes:**
- Arrow functions are modern; both syntaxes are valid
- Callbacks are powerful but take practice
- Array methods are used constantly in real projects
- Don't require `.reduce()`; it's advanced
- This sets them up for SvelteKit later

---

## **Week 8: October 19-25, 2026**
### Objects & Arrays: The Full Picture

**Topics:**
- Object literals (properties and methods)
- Arrays of objects
- Accessing nested data
- Combining loops with objects/arrays

**Activities:**
- Live code: Create a person object with properties
- Live code: Create an array of people (array of objects)
- Group exercise: Access nested data (`people[0].name`)
- Live code: Add a method to an object
- Challenge: Use loops/array methods with objects

**Homework:**
- Create an array of objects representing something meaningful
- Use array methods to find/transform/display them

**Teaching Notes:**
- Objects and arrays are the foundation of data structure
- Arrays of objects are how real data is organized
- Accessing nested data is crucial for real projects
- This is hard; go slow and use lots of examples

---

## **Week 9: October 26 - November 1, 2026**
### Capstone 1: Individual CLI Project

**Topics:** Applying Weeks 1-8 fundamentals

**Project:** Build ONE of these:
- **Calculator:** Take two numbers, perform operations
- **To-Do List:** Add, remove, list tasks (array of objects)
- **Quiz Game:** Ask questions, track score
- **Text Adventure:** Narrative with choices

**Requirements:**
- Use variables, functions, loops, conditionals, operators
- Use at least one object or array
- Get user input
- Handle edge cases

**Activities:**
- Help them choose a project
- Break it into steps (planning is key)
- Individual work with you as guide
- Debug together

**Deliverable:**
- Working `.ts` file
- 2-minute explanation

**Your Role:**
- Ask guiding questions, don't give answers
- Help them plan before coding
- Celebrate effort and problem-solving

**Teaching Notes:**
- This proves they understand Phase 1
- Some will finish early; give stretch challenges
- Some will struggle; that's normal
- This is their first real achievement—celebrate it!

---

## PHASE 2: WEB FUNDAMENTALS (4 Weeks)
### November 2 - November 29, 2026
**Goal:** Learn HTML, CSS, and vanilla JavaScript working together

**Note:** Thanksgiving week (Nov 26-27) will have reduced attendance. Plan accordingly.

---

## **Week 10: November 2-8, 2026**
### HTML & CSS Basics

**Topics:**
- HTML structure (semantic tags, common elements)
- CSS selectors and properties
- Box model (margin, padding, border)
- Basic layout (flexbox intro)

**Activities:**
- Live code: Build a simple page (header, nav, main, footer)
- Show: Why semantic HTML matters
- Live code: Style it with CSS
- Explain box model visually
- Group exercise: Apply margins, padding, borders
- Challenge: Use flexbox for layout

**Homework:**
- Create an HTML page with semantic tags
- Style it with CSS (colors, fonts, spacing)

**Teaching Notes:**
- Don't spend too long on HTML details
- CSS is more important for projects
- Flexbox is enough for basic layouts
- They don't need to be CSS experts; just functional

---

## **Week 11: November 9-15, 2026**
### JavaScript in the Browser & DOM

**Topics:**
- Selecting elements (`.querySelector()`, `.getElementById()`)
- Manipulating content (`.textContent`, `.innerHTML`)
- Event listeners (`.addEventListener()`)
- Manipulating classes (`.classList.add()`, `.classList.remove()`)

**Activities:**
- Live code: Select an element, change its text
- Live code: Add a click listener to a button
- Group exercise: Toggle a class on button click
- Live code: Show/hide elements
- Challenge: Multiple interactions

**Homework:**
- Create a button that does something when clicked
- Create a toggle that shows/hides content

**Teaching Notes:**
- The DOM is just JavaScript objects
- Selectors are the same as CSS
- Events are how user interactions trigger code
- Keep it simple; they don't need advanced DOM manipulation

---

## **Week 12: November 16-22, 2026**
### Guided Mini-Project: Weather App (Part 1)

**Topics:**
- Fetching data from APIs (`fetch()`)
- Parsing JSON
- Combining HTML, CSS, JavaScript

**Project:** Build a weather app that:
1. Takes city name as input
2. Fetches weather from OpenWeatherMap (free)
3. Displays results nicely

**Activities:**
- Live code: Show `fetch()` and how to use it
- Live code: Parse JSON response
- Build HTML structure together
- Guide them to style it
- Test together

**Deliverable:**
- Working weather app

**Your Role:**
- Provide scaffolding code
- Help debug
- Guide, don't code it for them

**Teaching Notes:**
- APIs are just URLs returning data
- Don't go deep on promises; just use them
- Error handling can wait
- This shows what's possible!

---

## **Week 13: November 23-29, 2026**
### Guided Mini-Project: Weather App (Part 2) & Wrap-up

**Note:** Thanksgiving week—reduced attendance likely. Keep it short and celebratory.

**Activities:**
- Refine weather app together
- Add error handling basics
- Improve UI/UX
- Celebrate the project

**Deliverable:**
- Polished weather app

**Teaching Notes:**
- This completes Phase 2
- Everyone now understands vanilla web development
- They're ready for SvelteKit (which solves the pain points they just felt)
- Celebrate! They've built something real.

---

## PHASE 3: SVELTEKIT FUNDAMENTALS (6 Weeks)
### November 30, 2026 - January 9, 2027
**Goal:** Learn SvelteKit. Get everyone comfortable building apps.

**Note:** Winter break (Dec 22 - Jan 1) cuts this phase short. Real teaching time: ~4.5 weeks.

---

## **Week 14: November 30 - December 6, 2026**
### Introduction to SvelteKit

**Topics:**
- Why frameworks exist (recap vanilla JS pain points)
- Component-based architecture
- Reactive variables in Svelte
- SvelteKit project setup

**Activities:**
- Reflect: "What was annoying about the weather app?"
- Explain: "SvelteKit solves these problems"
- Live code: Create a SvelteKit project
- Show project structure
- Live code: Simple counter component
- Key insight: `let count = 0; count++` just works!

**Homework:**
- Set up a SvelteKit project
- Create a simple counter

**Teaching Notes:**
- Frameworks solve real problems they already felt
- Reactivity is Svelte's magic; emphasize this
- Don't go deep on configuration; just show it works

---

## **Week 15: December 7-13, 2026**
### Components & Props

**Topics:**
- Component files (`.svelte`)
- Props (passing data between components)
- Event handlers
- Two-way binding (`bind:`)

**Activities:**
- Live code: Create a `Button` component with props
- Live code: Handle click events
- Live code: Use `bind:value` on input
- Group exercise: Build a reusable form component
- Challenge: Compose multiple components

**Homework:**
- Create a reusable component
- Use it in different ways

**Teaching Notes:**
- Props are how components communicate
- Binding is convenient but optional
- Component composition is powerful
- Keep it simple; they just need the basics

---

## **Week 16: December 14-20, 2026**
### Routing & Pages

**Topics:**
- File-based routing
- Pages (`+page.svelte`)
- Layouts (`+layout.svelte`)
- Navigation between pages

**Activities:**
- Live code: Create multiple pages
- Show: File structure = URL structure
- Live code: Create a shared layout
- Group exercise: Build a multi-page site
- Challenge: Nested routes

**Homework:**
- Create a 3+ page site with shared layout

**Teaching Notes:**
- File-based routing is automatic
- Layouts avoid code duplication
- This is starting to feel like real web development

---

## **Week 17: December 21 - January 3, 2027**
### WINTER BREAK
**No meetings**

**Optional for interested students:**
- Explore SvelteKit docs
- Build a small project
- Practice component creation

---

## **Week 18: January 4-10, 2027**
### Stores & Data Sharing

**Topics:**
- Svelte stores (writable stores)
- Sharing data across pages
- Updating stores from components

**Activities:**
- Problem: "How do we share data between pages?"
- Solution: Stores
- Live code: Create a store, use it
- Live code: Update a store
- Group exercise: Build a simple app with shared state (todo list, preferences, etc.)

**Homework:**
- Create an app using a store

**Teaching Notes:**
- Stores solve real problems (prop drilling)
- Not magic, just a pattern
- This is crucial for group projects later

---

## **Week 19: January 11-17, 2027**
### Server-Side Code Basics

**Topics:**
- Server vs. client code
- `+page.server.js` for data loading
- Why this matters (security, performance)

**Activities:**
- Explain: "Some code runs on the server"
- Live code: Load data server-side
- Compare: Server-side vs. client-side fetching
- Group exercise: Create a page that loads data on the server
- Show: Environment variables for API keys

**Homework:**
- Rebuild weather app in SvelteKit (server-side loading)

**Teaching Notes:**
- Server-side rendering is an advantage
- SvelteKit makes it easy
- This is production-ready architecture

---

## **Week 20: January 18-24, 2027**
### Capstone 2: Guided SvelteKit Project (Together)

**Topics:** Putting it all together

**Project:** Build a SIMPLE app as a club (pick one):
- **Task Manager:** Add/remove/list tasks (store + pages)
- **Simple Blog:** Display posts, view details (server-side data)
- **Movie Tracker:** Search and save favorite movies (API + store)

**Activities:**
- As a group, plan the app
- Build it together (you guide, they code)
- Everyone contributes
- Deploy together

**Deliverable:**
- Working SvelteKit app
- Everyone understands how it works

**Your Role:**
- Architect the structure
- Guide implementation
- Everyone codes along

**Teaching Notes:**
- This is the "synchronization point"—everyone at the same level
- Working together builds confidence
- Deployment shows it's real
- Now you're ready for independent projects

---

## PHASE 4: INDEPENDENT PROJECTS (4-5 Weeks)
### January 25 - June 18, 2027
**Goal:** Teams build something real, applying everything learned

**Note:** Built-in flexibility for holidays, testing periods, etc.

---

## **Week 21: January 25-31, 2027**
### Project Planning & Team Formation

**Activities:**
- Brainstorm: Real problems to solve
- Form teams (2-4 people, mixed ability)
- Define project scope
- Create a plan
- Assign tasks

**Constraints:**
- Must solve a real problem
- Must be completable in 4-5 weeks
- Must use SvelteKit
- Must use 1+ stores OR server-side data loading

**Your Role:**
- Help scope (too big is common killer)
- Ensure they have a plan

**Teaching Notes:**
- Small projects > ambitious projects
- Planning prevents disasters
- Mixed teams learn from each other

---

## **Week 22: February 1-7, 2027**
### Project Setup & Architecture

**Activities:**
- Teams set up SvelteKit project
- Create file structure
- Plan components and stores
- Assign who builds what

**Your Role:**
- Review architecture
- Point out issues (don't solve)
- Help them think through problems

**Deliverable:**
- Project skeleton
- Clear plan for next 3 weeks

---

## **Week 23-25: February 8 - March 7, 2027**
### Project Development (3 weeks)

**Note:** Feb 10-12 are faculty training days. Week might be shorter.

**Activities:**
- Teams code independently
- Weekly 15-min check-ins per team
- You help unblock, don't code
- Encourage testing

**Your Role:**
- Advisor, not coder
- Guide them to solutions
- Celebrate progress

**Teaching Notes:**
- This is where they learn by doing
- Debugging skills matter more than speed
- Small wins add up

---

## **Week 26: March 8-14, 2027**
### Polish & Testing

**Activities:**
- Fix remaining bugs
- Improve UI/UX
- Test thoroughly
- Prepare for deployment

**Your Role:**
- Help prioritize
- Guide on polish

**Teaching Notes:**
- Push for "done" over "perfect"
- Shipping is a huge achievement

---

## **Week 27: March 15-21, 2027**
### Deployment & Wrap-up

**Activities:**
- Deploy to Vercel (or similar)
- Write README
- Document what they learned

**Deliverable:**
- Live, deployed project
- README explaining it

**Teaching Notes:**
- Deployment is exciting
- Let them share the live link

---

## **Week 28: March 22-28, 2027**
### Presentation Prep

**Activities:**
- Prepare 5-minute presentations
  - What problem does it solve?
  - How does it work?
  - What did you learn?
  - Demo
- Practice presenting
- Prepare for Q&A

**Your Role:**
- Coach on presentations
- Encourage them

**Teaching Notes:**
- Public speaking is scary; be supportive
- Celebrate the learning, not just the product

---

## **Week 29: March 29 - April 4, 2027**
### Final Presentations & Celebration

**Activities:**
- Each team presents (5-10 min)
- Q&A
- Celebrate together

**Ideas:**
- Invite parents/teachers
- Have snacks
- Take photos
- Display projects on screen

**Your Role:**
- Emcee
- Ask good questions
- Celebrate effort

**Teaching Notes:**
- This is the culmination of their work
- Make it feel important
- Celebrate what they learned more than the final product

## FLEXIBILITY & BUFFERS

**Can adjust if ahead:**
- Add more practice in Phase 1
- Extend weather app
- Build a second mini-project in Phase 3

**Can adjust if behind:**
- Skip advanced array methods
- Simplify Phase 2 (just build static site + one interaction)
- Keep Phase 4 to group project only

**Built-in flexibility:**
- Winter break gives natural pause
- Project phase has extra weeks for buffer
- Weeks 29-30 can compress if needed

---

## TEACHING PHILOSOPHY

1. **Everyone reaches the same level** by Week 20 (end of Phase 3)
2. **Level-setting matters more than speed** — don't rush fundamentals
3. **Group projects are the goal** — Phase 1-3 prepare for this
4. **Celebrate learning** — the projects are proof of learning
5. **Your role shifts** from teacher (Phase 1) to guide (Phase 4)

---

## KEY MILESTONES

- **Week 9:** Everyone finishes Phase 1 (fundamentals locked in)
- **Week 13:** Everyone finishes Phase 2 (can build vanilla web apps)
- **Week 20:** Everyone finishes Phase 3 (can build SvelteKit apps)
- **Week 21-22:** Teams form with shared understanding
- **Week 28:** Teams deploy real projects
- **Week 29:** Teams present and celebrate

## FINAL NOTES

This curriculum prioritizes **level-setting** over breadth. You're not teaching "everything about web development"—you're teaching enough for everyone to:

1. ✅ Understand JavaScript fundamentals
2. ✅ Build basic web apps with HTML/CSS/JS
3. ✅ Use a real framework (SvelteKit)
4. ✅ Work together on projects

That's the goal. And it's a great one.

By June, you'll have teams shipping real apps solving real problems. That's success.

Good luck. You've got this. 🚀
